## 边传边校验改造（verify-after-transfer）
- 需求：原流程"全量拷贝完再统一校验"导致校验阶段磁盘 IO 读盘时间过长，改为"先传 FullFilelist_DEF.csv → 文件1传输+校验 → 文件2传输+校验"，多线程并行
- 实现要点：
  - `file_transfer.py` FileServerHandler 新增 `/filelist` 端点（响应头带 X-CSV-Date），返回源端 `F:\Appl\<YYYY-MM-DD>\FullFilelist_DEF.csv`
  - `_download_filelist()`：接收端传输前先下载清单到 F盘\Appl\<日期>\，失败返回 "" 不影响主传输
  - `download_files`/`_download_files_inner` 新增 `verify_after_transfer` 与 `pre_verified_out`；下载成功后放入 queue，`verify_worker_count = max(1, min(max_workers, 4))` 个独立线程做"存在+大小"轻量校验（不做 MD5，避免多读一遍盘）
  - 断点续传跳过的文件计入 `pre_ok_paths`；收尾 `_save_pre_verified()` 写 `pre_verified.txt` 确认清单（注意盘符根补 `\\`，否则得到相对路径 F:Appl\）
  - `verifier.py` `verify_csv`/`run_verification` 新增 `pre_ok_paths`：清单内已确认文件直接写 VerifyResult=Y 并跳过（仅 target_indices is None 时生效），completed_count 初值带上 pre_ok 数
  - `control.py` 传输时传 `verify_after_transfer=True, pre_verified_out=...`，校验阶段读确认清单构造 pre_ok_paths
- 已通过 3 个测试：`_test_preok.py`（增量跳过 3 场景）、`_test_filelist_e2e.py`（/filelist 端点）、`_test_download_verify.py`（完整下载+边传边校验+断点续传 early return）
- 临时输出文件 `_test_out.txt` 已删除；测试脚本 `_test_*.py` 保留在工作区
- 无新增依赖（queue/urllib 均标准库），重新打包 exe 无需改 build.ps1
