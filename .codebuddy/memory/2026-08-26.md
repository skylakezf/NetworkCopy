- `_test_device_transfer_e2e.py` 新增场景6 `test_auto_verify_after_transfer`（33 断言）

### 场景6 根因（关键发现）
**本嵌入式 Python 3.13.14 的 tkinter 禁止后台线程调用任何 tk 接口**：连 `self.ui.after(...)` / `StringVar.get()` 都会抛 `RuntimeError: main thread is not in main loop`（`after`→`_register`→`createcommand` 有线程检查）。之前的 `_verify_log`"改用 `after` 调度主线程"方案在此环境根本不可行——`_verify` 线程在 `winpe_var.get()`（control.py 2084 行）处直接抛异常，except 里 `_verify_log` 再调 `after` 又抛，线程静默死亡 → `_verify_done=False`、`run_verification` 未被调用。

### 修复方案：线程安全队列 + 主线程轮询
- `_start_auto_verification`：
  - winpe 标志在主线程读取后传参（不在后台线程访问 tk 变量）
  - 后台线程只 `self._verify_ui_q.put(("log"/"status"/"status_line"/"progress", ...))`
  - 主线程 `self.ui.after(100, self._poll_verify_ui)` 启动轮询，校验/上传线程存活期间持续自轮询（150ms）
- `_poll_verify_ui`：主线程 drain 队列并渲染（`_log`/`set_verify_online_status`/`_set_status`/`_set_progress`）
- `_upload_verifier_report`：记录 `self._verify_upload_thread` 供轮询判断存活
- `_on_skip_verify` 兜底路径同样改为队列（原 `_log_safe` 直接 after 同 bug）
- 测试 `_fake_verify` 必须模拟 `run_verification` 把 ZIP 路径 append 进 `report_zip_out`，否则报告上传与 `_verify_report_path` 不触发

### 通用教训
- 此环境任何后台线程直接调 tkinter（含 `after`/`StringVar.get`/`config`）都会抛 RuntimeError，正确姿势是"后台线程入队 + 主线程 after 轮询"
- 测试中 patch 需命中模块级绑定：`control.py` 用 `from verifier import run_verification`，须 patch `ctl_mod.run_verification`
- 最终结果：e2e 33/33、`_test_ui_full` 48/48、`_test_user_cases` 21/21、`_test_device_replacement` 25/25、`_test_func_full` 全部通过，FAIL 0
