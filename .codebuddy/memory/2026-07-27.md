## 修复：源端 HTTP 重定向服务启动失败 WinError 10013
- 现象：源端日志报 "HTTP 重定向服务启动失败 (winerror10013) ... 访问权限不允许"。
- 根因：重定向服务绑定 80 端口；80/443 是 0-1023 特权端口，需 SYSTEM/管理员才能绑定。用户此前将 9999(高端口, 免特权) 改为 443/80，反而**增加**了权限要求（与"避免管理员权限问题"初衷相反）。10013=权限拒绝（10048=端口占用，socket 已设 allow_reuse_address 可防御）；无法用 SO_REUSEADDR 修复。
- 关键点：该异常**已被捕获、非致命**；客户端永远只用 HTTPS，重定向服务不可用不影响文件传输；443 的 HTTPS 文件服务器照常运行。
- 修复（file_transfer.py FileServer.start 的 except 块）：区分 winerror——10013 明确提示"进程无权绑定 80 特权端口，但 HTTPS 不受影响、传输正常"，10048 提示端口被占用，其余原样；均标注"不影响 HTTPS 传输"。
- 用户指引：若确实要让 80 重定向可用，须以 SYSTEM/管理员运行或释放 80 端口；否则可安全忽略。注意 443 同为特权端口，若会话非 SYSTEM，443 也可能 10013（本次未出现，说明 443 已成功）。

## 设计注意（端口/权限）
- 误区提醒：高位端口(如 9999)无需特权；80/443/1024 以下均属特权端口，绑定需 SYSTEM/管理员。WinPE 默认 SYSTEM 通常无碍，但部分 PE 会话或非 SYSTEM 上下文会 10013。重定向服务(80)对本工具无功能价值(客户端仅 HTTPS)，属 best-effort。

## BUG 修复：Tooltip 提示框鼠标移开后不消失
- 现象：tooltip 能显示，但鼠标移开后提示框残留占屏。
- 根因：原实现依赖 `<Leave>` 事件隐藏。部分 ttk 控件 (Combobox/Button) 的 `<Leave>` 不可靠/不冒冒；曾改用 `bind_all("<Motion>")` 全局监听仍无效 (用户反馈"问题依旧")。
- 修复 v2 (定时器轮询, 彻底可靠)：重写 Tooltip —— 仅 `<Enter>` 调度显示；显示后用 `self.widget.after(200, _poll)` 定时器轮询，每 200ms 调 `_pointer_inside()` 判断鼠标是否仍在控件内，移出即 `_hide()`+`after_cancel` 停止轮询。`_pointer_inside` 用 **坐标差值** `winfo_pointerx()-winfo_rootx()` 与 `winfo_pointery()-winfo_rooty()` 比较控件宽高，消除窗口在屏幕绝对位置偏移的影响 (不再直接比绝对坐标)。完全不依赖 `<Leave>`/`<Motion>` 事件触发隐藏。
- 修复 v4 (用户反馈"依旧")：核心根因修正。之前怀疑 `winfo_pointerx` 冻结，但更可能是 **`overrideredirect` 的提示框窗口正好盖住鼠标，拦截了鼠标事件**，导致全局 `<Motion>`/`widget <Leave>` 在鼠标移到提示框区域时不再触发 → 无法隐藏。修复：给提示框加 `tip.wm_attributes("-disabled", True)` 使鼠标事件穿透（不拦截），并保留根窗口 `bind_all("<Motion>")` 用 `event.x_root` 判断 + 控件 `<Leave>` 辅助；再加 **自动消失兜底定时器** `autohide=5000ms`（`after(5000, self._hide)`），保证即使所有事件都失效，提示框最多 5 秒后也强制消失，绝不永久占屏。去掉了原本依赖 `self._last` 的 250ms 轮询定时器（因 last 仅在 Motion 更新，Motion 不触发则 last 为 None 永不隐藏）。
- 验证：ui.py py_compile 通过。
- 关键经验：本工具 tk 环境（嵌入 Python 3.13.14-embed / WinPE）对悬浮提示框隐藏事件极不可靠，必须用「-disabled 穿透 + 自动消失兜底」双保险；纯靠 `<Leave>`/`<Motion>`/坐标轮询均失败过。
