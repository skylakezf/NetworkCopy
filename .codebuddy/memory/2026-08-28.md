## 接收端点击开始传输后崩溃 —— 已修复（线程安全 UI 调度全面整改）
- 根因：`_connect_and_download` 等**后台线程**直接调 `self.ui.after(...)`，本嵌入式 Python 3.13.14 的 tkinter 会抛 `RuntimeError: main thread is not in main loop`（实测确认），回调永不执行 → 传输完成后 UI 收不到完成通知（卡死），打包环境下甚至触发 Tcl 崩溃。
- 修复方案：复用既有"队列 + 主线程轮询"模式，在 `Controller` 增加统一基础设施：
  - `_post_ui(fn, *args, **kwargs)`：主线程直接执行；后台线程入 `_ui_q` 队列
  - `_poll_ui_q()`：`init()` 时 `after(50, ...)` 常驻轮询 drain 队列
  - `_ui_after(ms, cb)`：线程安全一次性延时调度（后台线程版 `after`，返回 None）
  - `_log`/`_set_status`/`_set_progress`/`_log_import`/`_log_export` 全部改为线程安全包装（自动转主线程）
- 整改的后台线程调用点（15 个线程 + 各类回调）：网卡/磁盘/分区扫描、`_setup_source_network`、`_setup_target_dhcp`（倒计时改用 `_start_dhcp_countdown` 主线程方法）、`_update_discover_list`、`_monitor`（网络监控）、`_connect_and_download`（核心，含 `_progress`/完成回调）、`_on_source_report`、配置导出/压缩上传/导入线程、`_partition_progress`、`_verify_online_progress`、`_resolve_conflicts`（对话框）、`_apply_manual_ip`/`_apply_target_manual_ip`（顺带修正 msg2 打错为 msg 的日志 bug）。
- 校验/上传线程原本已用 `_verify_ui_q` 队列，未改动。
- 验证：新增 `_test_thread_safe.py` 7/7 PASS（含直接 `app.after` 在后台线程确抛 RuntimeError 的对照）；`_run_ui_timed.py`（`_test_ui_full.py`）全量 PASS。
- 经验：**凡后台线程更新 UI 一律走 `_post_ui`/线程安全包装；需要 after id 做 after_cancel 的周期任务必须转主线程方法注册**。

## 断线处理机制修复（已完成，重要）
- 用户报告：拷贝中拔线后，发送方误显示"传输完成"，接收方误进入配置导入页。
- **根因1（源端）**：`FileServer.is_transfer_done` 含"15 秒空闲兜底"——接收端断网后不再发请求，同样满足空闲条件 → 源端误判完成。修复：`is_transfer_done` 只认显式 `/report done`；`control._poll_source_done` 新增断开判定（曾连接 + 无 done + 空闲 > `SOURCE_IDLE_TIMEOUT=45s`）→ 调用新增的 `_source_mark_interrupted()`（解除全屏锁定、显示中断提示、恢复"重新启动传输"按钮、停服务器，绝不进完成页）。45s 取 30s 边传边校验 join 上限 + 余量。
- **根因2（接收端）**：`_on_download_complete` 原在开头**无条件** `_report_to_source({"done": True})`；且 `success=False 且 files>0`（部分文件失败、网络监控未及时判定 `_network_down`）时无 return，继续走"传输完成→配置导入"。修复：done 只在成功分支发送；新增 `not success and files>0` 分支 → 显示"传输未完成"提示、恢复"重新接收"按钮，不进入配置导入/校验/总结页。
- 辅助：`_start_source_server` 启动时重置 `FileServerHandler.transfer_done_flag/ever_connected/last_activity`（防上一轮残留导致新一轮立即误判）。
- 新增专项测试 `_test_disconnect_handling.py`（6 用例：源端空闲不判完成/done 判完成、接收端部分失败不误入导入/成功上报 done、源端轮询中断/完成两路径）。回归：UI 60/60、功能 30/30 通过。
