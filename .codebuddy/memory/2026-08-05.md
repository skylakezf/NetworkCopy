## 修复：`.dat` 后缀过滤误杀微信数据文件

- **问题**：`SKIP_FILE_SUFFIXES` 中包含 `.dat`，原意是跳过 `NTUSER.DAT`（Windows 用户注册表，PE 下被系统锁定）。
  但微信的数据文件（聊天记录、图片缓存等）均以 `.dat` 后缀存储，导致 `xwechat_files` 整个文件夹被跳过传输。
- **根因分析**：
  1. `.dat` 后缀全局过滤 → 微信所有 `.dat` 文件被跳过
  2. 空目录不会被创建在目标端（`[N] 文件不存在` 日志）
  3. `NTUSER.DAT` 实际上会被 `os.stat()` 失败 + 持久化跳过列表兜底，不需要全局后缀过滤
- **修复**：从 `SKIP_FILE_SUFFIXES` 中移除 `.dat`，保留 `.tmp` 和 `.log`，新增 `SKIP_FILENAMES = {"ntuser.dat"}` 精确跳过锁定文件
- **涉及文件**：`file_transfer.py:57`

## 修复：`escape_csv` 导致含逗号文件校验失败（误报 `[N] 文件不存在`）

- **根因**：`calc_allocation_migration.py` 中 `escape_csv()` 将路径中的 ASCII 逗号 `,` 替换为全角逗号 `，`，导致 CSV 中的路径与磁盘实际路径不一致。文件已成功传输，但校验器用 CSV 的错路径去检查，全报 `[N] 文件不存在`。
- **额外发现**：
  1. `calc_allocation_migration.py` 的 `SKIP_FILE_SUFFIXES` 只有 `.tmp`，缺少 `.log` → `.log` 文件出现在 CSV 但不被传输 → 校验误报
  2. 两处代码的过滤器未对齐，造成 CSV 与传输列表不一致
- **修复**：
  1. `escape_csv` 不再替换逗号（Python csv.writer 会自动对含逗号字段加引号转义），改为只做 `/`→`\` 标准化 + 去末尾空格
  2. `calc_allocation_migration.py` 添加 `.log` 到 `SKIP_FILE_SUFFIXES`、`ntuser.dat` 到 `SKIP_FILENAMES`，与 `file_transfer.py` 对齐
  3. `should_skip_file` 增加大小写不敏感的文件名精确匹配
- **涉及文件**：`systemconfig/calc_allocation_migration.py:33-34,58-66,97-99`

## 修复：verifier.py 三层防御兼容旧版 CSV 的全角逗号路径

- **问题延伸**：虽然 `escape_csv` 已修复，但旧版生成的 CSV 中路径仍含全角逗号 `，`。校验器读取这些 CSV 时路径不匹配，持续误报 `[N] 文件不存在`。且重试逻辑用错误路径尝试下载，在极端情况下可能在目标盘多写一个全角逗号版本的文件。
- **完整链路复盘**：
  - 磁盘扫描 (`file_transfer.py`)：`os.walk` 使用实际文件系统路径 (ASCII 逗号) ✅
  - 文件传输：JSON 列表用实际路径发起下载 ✅
  - CSV 生成 (`calc_allocation_migration.py`)：`escape_csv` 将 `,`→`，` ❌
  - 校验 (`verifier.py`)：读 CSV 损坏路径 → `os.path.isfile` 失败 → 误报 ❌
  - 校验重试：用损坏路径请求服务端 → 返回空数据 / 404 → 理论上不写文件，但风险存在
- **修复 (三层防御)**：
  1. **校验前自动修复 CSV**：`_repair_csv_in_place()` 在 `run_verification` 开始时检测并替换 `，`→`,`，写入修复后的 CSV。时机在 GTMC 路径替换之前。
  2. **校验中兜底**：`_verify_single_row` 当 `os.path.isfile` 失败时，尝试 `_normalize_csv_path` 后再查，匹配则视为通过。
  3. **重试前兜底**：`_retry_missing_files_inner` 同样尝试修复路径，若修复后文件已存在则跳过重试，同时修复 CSV row 中的路径。
- **涉及文件**：`verifier.py:28-90 (新增), 711-720, 831-839, 1262-1264`

## 新增：传输过程中网络断开检测

- **需求**：传输过程中如果网络断开（网线松动等），应停止等待并提示用户检查网线连接
- **设计**：
  1. `control.py` 新增后台网络监控线程 `_start_network_monitor`/`_stop_network_monitor`
  2. 监控线程每 3 秒 TCP 连接源设备 `server_ip:9999`（超时 2 秒），连续 3 次失败判定为断网
  3. 断网时设置 `self._network_down = True`，`_check_stop()` 返回 `"network_down"` 信号
  4. `file_transfer.py` 的 `_check_stop` 将 `"network_down"` 视为停止信号（与 `"cancel"` 同等处理）
  5. `_on_download_complete` 检测到网络断开时，停止等待，显示错误提示 "网络连接已断开 — 请检查网线连接后重新开始传输"
- **涉及文件**：
  - `control.py:6 (新增 import socket), 93-94 (新增状态), 1268-1297 (新增监控方法), 1467-1469 (扩展 _check_stop), 1478-1479/1488-1490 (启动/停止监控), 1513-1531 (处理 network_down)`
  - `file_transfer.py:1684-1698 (扩展 _check_stop 处理 "network_down")`
