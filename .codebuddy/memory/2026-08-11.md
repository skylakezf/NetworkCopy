## 修复：发送端传输页验证码横幅不显示（UI 可操作性）

- **问题**：发送端在"准备开始传输"(步骤3连接页)能看到验证码框，但点击"开始传输"进入步骤4传输页后验证码横幅消失，导致目标端用户无法读取验证码。
- **根因分析**（三个叠加问题）：
  1. **pack 位置错误**：`_auth_banner_frame` 首次在 `_on_role_selected("source")` 时通过 `show_auth_code("----")` pack，此时步骤4其它控件早已构建并 pack 完毕 → 横幅被排到页面**最底部（日志区下方）**，被 `expand=True` 的日志区挤出可视区域。
  2. **显示时机太晚**：`_start_source_server` 中 `show_auth_code` 在最后才调用，前面有 `_add_firewall_exception`（`subprocess.run` 最多阻塞 10 秒）、证书生成等耗时操作，用户进入传输页后长时间看不到验证码。
  3. **页面切换后 pack 状态可能丢失**：步骤切换时 `pack_forget` 所有页面，再次 pack 后横幅位置可能错乱。
- **修复**：
  1. `ui.py show_auth_code`：用 `before=self.tk_label_transfer_status` 固定横幅位置在状态标签之前（紧接"传输中..."标题），避免被排到页面底部。
  2. `ui.py go_step`：进入步骤 4 且角色为发送端时，重新调用 `show_auth_code` 断言横幅可见。
  3. `control.py _start_source_server`：先生成验证码并立即 `show_auth_code`（在证书生成/防火墙等耗时操作之前），让横幅立即出现。
  4. `control.py _on_role_selected` target 分支：新增 `hide_auth_code()`，防止从发送方角色切换过来时横幅残留。
- **涉及文件**：`ui.py:289-295, 1326-1335`, `control.py:311-315, 1191-1197`

## 修复：断网后仍继续拷贝重试 + 断网提示不及时

- **问题**（用户实测日志）：断网后批次/单文件仍在重试 3 次（`[_] 批次重试 1/3`、`2/3`、`[X] 批次下载失败`），且 UI 提示要等传输结束/网络恢复才显示。
- **根因**：
  1. `_download_batch_with_retry` / `_download_single_file_with_retry` 的重试循环**不检查 stop_check**，`_network_down=True` 后仍盲目重试 + `time.sleep` 傻等后退
  2. 断网提示只在 `download_files` 返回后（`_on_download_complete`）才显示
  3. 监控用 TCP connect 探测，用户要求改用 ICMP ping 更快
- **修复**：
  1. `file_transfer.py`：新增 `_TransferCancelled` 异常 + `_sleep_interruptible()`（0.1s 轮询可中断睡眠）；两个重试函数加 `stop_check` 参数，循环开头和后退期间检查，触发即抛 `_TransferCancelled`
  2. `_download_files_inner`：`_check_stop()` 改为返回 `"cancel"`/`"network_down"`/None 字符串（区分原因）；提交批次/单文件任务时传 `stop_check=_check_stop`（关键字参数）；`as_completed` 捕获 `_TransferCancelled` 立即取消剩余任务；日志区分"传输中断(网络已断开)"vs"传输已取消(用户中止)"
  3. `control.py`：监控线程改用 ICMP ping（`_ping_host` 用 `subprocess ping -n 1 -l 1 -w`，1 字节包），每 1 秒探测、连续 3 次失败判断网；ping 工具不可用时 `_host_reachable` 回退 TCP 探测；检测到断网**立即** `ui.after(0, _on_network_lost_ui)` 弹出提示（不等传输结束）
  4. 新增 `_on_network_lost_ui`：显示红色错误条 + 按钮"重新接收"
- **测试**：`_test_func_full.py` 新增 H4-H8（`_sleep_interruptible` 中断、单文件/批次重试断网立即中止、后退期间中断、`_ping_host` 可达性），共 29 项全通过
- **涉及文件**：`file_transfer.py:1021-1086,1298-1365,1711-1739,1843-1904`, `control.py:1271-1360`, `_test_func_full.py`

## 修复：断网检测全面放弃 ICMP ping，改用纯 TCP 探测

- **问题**（用户实测两次）：ICMP ping 被 Windows 防火墙默认拦截，导致网络正常时误报"网络连接已断开"。
- **决策**：放弃 ICMP ping，全面转为 **TCP 9999 端口探测**（传输实际通道，端口已放行，TCP 握手由内核完成，最可靠）。用户确认此方向。
- **修复**：
  - `control.py`：删除 `_ping_host` 方法；`_host_reachable` 简化为纯 `socket.create_connection((ip, 9999), timeout=2)`；日志措辞改为"连续 N 次无法连接 ip:9999"
  - 每 1 秒探测一次，连续 3 次失败判定断网
- **测试**：`_test_func_full.py` 删除 ping 相关测试（H8 旧、H10），新增 H8（TCP 通→可达）、H9（TCP 失败→不可达），共 30 项全通过
- **涉及文件**：`control.py:1273-1324`, `_test_func_full.py`
